# LORDHAND 移植总纲 — Three.js → TAPTAP MAKER (UrhoX)

## 元信息
- **源项目仓库**: https://github.com/FilthyFrost/lordhand.git
- **源引擎**: Three.js r160 (WebGL, JavaScript ES6)
- **目标引擎**: TAPTAP MAKER / UrhoX (Lua 5.4, Bullet Physics, PBR)
- **目标平台**: Windows PC（预留移动端）
- **视角**: FPS 第一人称（自实现相机，不使用内置 ThirdPersonCamera）
- **美术方向**: 还原 Acid Holy Shader 风格（顶点扭曲 + 卡通渲染 + 描边）

## 移植阶段规划

### 第 1 阶段：基础框架 (01 + 02 + 04-基础)
**目标**: 能在 MAKER 中以 FPS 视角看到静态地图

1. 搭建 MAKER 项目结构
2. 实现 FPS 相机（无 ThirdPersonCamera）
3. 实现 JSON chunk 数据加载 → CustomGeometry 渲染
4. 实现基础空间哈希碰撞

**验收标准**: 按 WASD 移动，鼠标转向，能看到彩色方块世界，不穿墙

### 第 2 阶段：角色移动 (03)
**目标**: 完整移动手感

1. 重力 + 基础跳跃
2. 二段跳
3. 冲刺（3方向）
4. 贴墙滑行 + 攀爬
5. 轨道滑行
6. 气球弹跳

**验收标准**: 所有移动机制可用，手感接近原版

### 第 3 阶段：战斗核心 (05 + 手模型)
**目标**: 能射击并命中环境

1. 程序化手掌模型（FPS视图）
2. 6针资源系统
3. LMB 散射/连射
4. RMB 单针/蓄力大招
5. 弹射物物理 + AABB 碰撞

**验收标准**: 4种攻击模式均可用，弹射物与地图碰撞正确

### 第 4 阶段：敌人系统 (06)
**目标**: 有敌人可以打

1. DemonBase AI 状态机
2. 程序化 Soulfire Skull
3. 程序化 Flayed Vessel
4. 程序化 Gluttonous Maw
5. 注册表 + 生成/销毁

**验收标准**: 敌人生成、追踪、受击、死亡流程完整

### 第 5 阶段：打击感 (07)
**目标**: 战斗有反馈

1. 命中停顿（时间缩放）
2. 方向性相机冲击
3. 粒子爆发（命中/死亡）
4. 屏幕闪白

**验收标准**: 攻击命中时有明显视觉反馈

### 第 6 阶段：UI + 音效 (08 + 09)
**目标**: 完整游戏体验

1. 主菜单 + 设置
2. 战斗 HUD（生命、弹药、准星、高度）
3. 所有音效 .ogg 集成
4. 背景音乐

**验收标准**: 从启动到游戏的完整流程

## 技术映射总览

| 原始 (Three.js/JS) | 目标 (MAKER/Lua) |
|---------------------|------------------|
| `THREE.Scene` | `Scene:new()` |
| `THREE.PerspectiveCamera` | 自建 FPS Camera Node |
| `THREE.WebGLRenderer` | 引擎内置 PBR Renderer |
| `THREE.BufferGeometry` | `CustomGeometry` |
| `THREE.InstancedMesh` | `StaticModel` 批量节点 或 CustomGeometry |
| `THREE.ShaderMaterial` | `Material:new()` + Technique |
| `THREE.MeshBasicMaterial` | PBR `PBRNoTexture.xml` 或 `NoTextureUnlit.xml` |
| `requestAnimationFrame` | `SubscribeToEvent("Update", ...)` |
| `document.addEventListener("keydown")` | `input:GetKeyDown(KEY_X)` |
| `pointer lock API` | `SampleInitMouseMode(MM_RELATIVE)` |
| `Web Audio API` | `SoundSource` + .ogg 文件 |
| AABB 碰撞（自实现） | 自实现 Lua AABB（不用 Bullet） |
| `window.xxx` 全局 | Lua 全局 table / require 模块 |
| ES6 `import/export` | `require()` / return table |
| `THREE.Vector3` | `Vector3(x, y, z)` |
| `THREE.Color(hex)` | `Color(r, g, b, a)` (0~1 浮点) |
| `Math.floor` | `math.floor` |
| Array `[0]` 起始 | Table `[1]` 起始 |

## 关键约束提醒

1. **不使用 KinematicCharacterController** — 原游戏是自实现物理，MAKER 移植也应自实现（方案A：纯 Lua AABB）
2. **不使用 ThirdPersonCamera** — FPS 视角，相机直接绑定玩家节点
3. **坐标系**: MAKER 是 Y-up 左手系，与 Three.js 的 Y-up 右手系不同 → Z 轴可能需要翻转
4. **单位**: Three.js 原游戏单位 ≈ 1米，MAKER 单位 = 1米，直接对应
5. **颜色格式**: Three.js `0x00ffff` (整数) → MAKER `Color(0, 1, 1, 1)` (RGBA 0~1)
6. **数组索引**: JS `array[0]` → Lua `table[1]`
